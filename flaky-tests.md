- 2026-10-31: `ui/e2e/bottom-drawer-restore.spec.ts` › "shows another terminal when the remembered one was destroyed" failed in two full `pn test` runs with `apiResponse.json: Response has been disposed` at `ui/e2e/helpers.ts:116`; the intervening full Playwright run passed all 333 tests. - 2026-10-31: `ui/e2e/serial/terminal.spec.ts` › "keeps keyboard focus in the terminal after selecting text with the mouse" failed in the full `pn test` run and in 1 of 3 isolated reruns (passed in the other 2, and once on the commit before the vault UI). - 2026-10-31: `ui/e2e/serial/terminal.spec.ts` › "keeps keyboard focus in the terminal after selecting text with the mouse" failed again in a full `pn test` run (the first `printf` output never arrived) and in isolated reruns, both with and without the attach-size and focus fixes (2 of 14 isolated runs failed on the unchanged code). A captured failure in the second `selectMarker()` showed the marker row rendered where its bounding box says, yet a horizontal drag across it selected the 3–4 prompt rows below it. The terminal was scrolled to the bottom with `scrollTop` 83, `clientHeight` 274 and 17 px rows, so the scroll offset was not a whole number of rows. Fixed: the offset was a red herring. The starship prompt arrived and scrolled the screen between measuring the marker row and pressing the mouse, so the first drag selected the wrong row. Every retry then held Shift, and Shift-press extends the existing selection, so it stayed anchored on that row and selected only the prompt rows between it and the marker. Each retry now returns focus to the shell input first, which drops the earlier selection. Forcing the first drag 5 rows low failed 3 of 3 runs before the fix and passed 5 of 5 after it. Before the fix, 4 of 15 and 1 of 15 isolated repetitions failed; after it, 30 of 30 repetitions plus 15 separate isolated runs passed. The missing first `printf` output did not recur in about 80 runs and is unexplained.
